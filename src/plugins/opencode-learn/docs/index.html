opencode-learn

Passive observation system for OpenCode — learn how you work, detect patterns, promote corrections to rules.

v0.1.0 · OpenCode Plugin · Passive · 13 tables

What It Is

opencode-learn is a passive plugin that silently captures your OpenCode sessions into a local database so you can later analyze your patterns, preferences, and workflow — without changing how you work.

Zero Effort

No Buttons, No Commands

Install once. It runs silently in the background. You never interact with it.

Cross-Project

Central Database

All projects share one DB at ~/.local/share/opencode-learn/learn.db. Query across projects.

Deterministic

No LLM Required

Regex classifiers only. Cheap, fast, auditable. No model calls, no hallucination risk.

Graduation Gate

Recurring → Rules

One-off corrections stay as data. Only recurring patterns (freq ≥ 2) graduate into proposed rules.

Architecture

Three-layer system: Collection → Storage → Analysis.

Three-layer system: OpenCode emits events → Plugin captures and classifies → Analysis tool clusters and proposes rules for human review

Correction Detection Pipeline

Every user prompt is checked: is it responding to a prior assistant output? Does it contain correction signals? Does it match a known pattern?

Analysis & Promotion Pipeline

Analysis clusters corrections by pattern, gates on frequency, and proposes rules for human review

Correction Classification Kinds

Every detected correction is classified into one of five kinds. Each kind maps to a different promotion path.

skill_misuse

Wrong tool or approach

"don't use grep, use ripgrep instead"

Promotion: Update tool preferences in agent instructions

memory_update

New context or facts

"actually the project uses React 18"

Promotion: Update project-specific context in AGENTS.md

behavioral

Tone, format, verbosity

"don't explain, just do it"

Promotion: Add communication style instructions

rule

Hard constraints

"never modify package.json"

Promotion: Add permissions or agent prompt rules

preference

Softer guidance

"I prefer camelCase for variables"

Promotion: Add softer guidance to agent instructions

Known Limitations

Not captured

Skill activations

No EventV2 event fires when a skill triggers. Skills are injected as text into the system prompt.

Workaround: Analyze prompt text for skill trigger keywords at query time.

Not captured

Session boundaries

session.created and session.deleted are V1 events, not available in EventV2.

Workaround: Poll OpenCode's own SQLite DB for session timestamps.

Not captured

Undo / Redo

No event fires when the user runs /undo or /redo.

Workaround: Detect git checkout / git restore in shell commands.

Heuristic

Correction false negatives

Regex classifier misses subtle corrections. Only catches explicit pushback language.

Trade-off: Prefer false negatives over false positives. Analysis phase finds patterns over time.

Quick Start

1

Install

Add to ~/.config/opencode/opencode.json: "plugins": ["path/to/opencode-learn"]

2

Use OpenCode normally

Work as you always do. The plugin collects data silently. No interaction required.

3

Check your data

sqlite3 ~/.local/share/opencode-learn/learn.db "SELECT count(*) FROM tool_call"

4

Run analysis

bun src/analyze.ts — see correction patterns and graduate candidates.

5

Promote to rules

bun src/analyze.ts --apply — write proposals to proposed_rule table, then review and approve.
